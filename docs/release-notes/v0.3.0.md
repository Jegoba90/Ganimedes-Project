### What changed

**The log now states the rules it was judging under.** Every run opens with an
entry of `kind: "session"` carrying the version, the wrapped command with its
arguments, and the deny and approval lists actually in force. It is hashed,
signed and chained exactly like a tool call, so those conditions cannot be
restated afterwards without breaking every hash that follows.

This closes a real hole rather than adding a feature. Until now
`"decision":"allow"` was identical bytes whether a policy examined the call and
permitted it or no policy was ever loaded, so a log of nothing but `allow` could
not tell an attentive gatekeeper from an open door. Empty lists are written as
`[]` rather than omitted, because "nothing was denied" is precisely the fact an
absent field would hide.

**Your existing logs still verify.** A tool call carries no `kind` at all, which
keeps its bytes identical to what every earlier version wrote. That is tested
from frozen bytes, and the log a published `v0.2.0` binary wrote was re-verified
with this build before the change shipped.

**`verify` got stricter.** It now refuses an entry whose kind it cannot classify,
or whose fields contradict the kind it claims. That check runs after the hash and
the signature, so it never reports tampering: it reports a record this build
cannot judge, which is the honest thing to say about one.

**`scan` stops implying an all-clear.** Its count invited reading the unflagged
tools as safe. The output now says what the keyword list covers, destruction,
execution, state change, money, network egress and secrets, which is also the
cheapest way to say what it leaves out: a tool that only reads your data matches
none of it.

**What found all this.** The first run under a real MCP client instead of the
throwaway test client every earlier smoke used. It also exposed a limit that is
documented rather than fixed: a wrapped server can renegotiate its own scope with
the client after launch, and the gateway forwards that exchange without recording
it. The session header states the conditions at launch, which narrows that gap
without closing it. See `docs/TECH_DEBT.md` TD-4.

Minor rather than patch: the on-disk log format gained an entry kind. Upgrading
is still replacing one static file.
