### What changed

**The Go package page now explains how to use the command.** The package
comment introduces the gateway, installation, server wrapping, policy and
verification, with navigable headings and runnable command shapes. The
explanation of Go's entrypoint and repository layout remains in `main.go` as
an implementation comment, where contributors can still find it.

**The command has its own README.** pkg.go.dev reads documentation for the
command's directory; the repository's root README does not fill that page.
The new command README adds status badges, a compact feature table,
installation and first-run examples, plus links to configuration and security
limits. The full guide stays in the root README rather than being copied
wholesale into the command's entry.

### How it was found

Opening the command on pkg.go.dev showed an overview about `package main`
and internal wiring, with no installation or usage guidance. The page also
lagged behind the newly published tag until the module version was requested
through Go's proxy. The package documentation comes from the indexed source,
so improving the published text requires a new immutable module version.

### Why a patch

Only documentation and comment placement change. The entrypoint still calls
the same CLI, with the same commands, exit codes, policy decisions, audit
format and forwarded bytes. No dependency or runtime behavior is added.
