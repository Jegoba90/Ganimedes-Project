### What changed

**1.0.0 is a promise, not a feature.** The scope is the one every 0.x release
shipped: a gateway wrapping one MCP server, a signed and hash-chained audit log, a
deny-list, and human approval for flagged tools. What is new is a commitment
about change. From here, the CLI, its exit codes, the config format and the
ability to verify existing logs only break in a 2.0. The README's "Stability"
section says exactly what is covered and what is not.

It ships together with the largest set of fixes so far, from a review that read
the code adversarially against the constitution instead of against its own tests.

**Every `tools/call` is now judged.** A call with no `id`, or one whose
parameters failed typed decoding, used to pass to the server without a policy
decision. JSON that two parsers can read differently is refused: duplicate
members, case variants of the fields the gateway judges, invalid Unicode,
trailing values. For example, `{"name":"read_file","name":"delete_file"}`
could be judged as one tool and executed as the other. Each refusal is audited
with the exact bytes received.

**`verify` catches edits it used to miss.** It rebuilt each entry from Go
structs, so a field it did not know was dropped before the signature check.
It now checks the stored entry whole. Numbers were canonicalized through
IEEE-754, so `9007199254740992` could be edited to `9007199254740993` without
changing the signature. New call records sign a `content_hash` that pins
numbers exactly.

**The approval page answers only to its own address.** A web page could use DNS
rebinding to read the local page and its token, or frame it to disguise the
Approve button. The page now serves only the exact Host it printed, refuses to
be framed, and bounds request size and time.

**Two gateways on one log are refused, and a killed gateway leaves nothing
behind.** Two writers used to fork the hash chain. The log is now held by a
kernel lock, which also covers hard links and is released by the operating
system when the process ends, including when the MCP client kills it.

**Smaller fixes:**
- An existing public key is never overwritten. It used to be replaced when its
  private key went missing, which made every older log unverifiable.
- Memory is bounded: 16 MiB per message and 1024 pending calls.
- `scan` reads every page of `tools/list` instead of the first.
- `verify` honours `GANIMEDES_SIGNING_KEY`.
- Building from source now requires Go 1.26.10. On Go 1.26.5, `govulncheck`
  reported 14 standard-library advisories as reachable; on 1.26.10 it reports
  none.

### Before you upgrade

- **Verify logs with a binary at least as new as the one that wrote them.** A
  `ganimedes verify` from v0.3.3 or earlier does not know `content_hash` and
  reports a genuine new log as `TAMPERED`. The other direction works: this
  version verifies logs written by earlier ones, and continues their chain.
  A log started by v0.3.3 and appended to by this build verified intact, old
  records and new together.
- **The config file is strict.** Only `command`, `args`, `deny` and `approve`
  are accepted, spelled exactly, each once. A misspelled or duplicated field
  used to be ignored, and is now an error at startup. Load it once by hand, for
  example with `ganimedes scan --config <path>`, before a client launches it.
- **`verify` takes one log and no unknown flags.** It used to treat every
  argument as the log path in turn, so `verify a.jsonl b.jsonl` checked only
  `b.jsonl` and printed OK, even with `a.jsonl` tampered. A second path or an
  unknown flag now exits `2`. A script that verifies several logs needs one
  `verify` per log.
- **Each wrapped server needs its own `--log`.** A second gateway on a log
  already in use exits with an error naming the log. The default log is
  `ganimedes-audit.jsonl` in the current directory, so two servers launched
  from one directory without `--log` will now collide.

### How it was found

A review on 2026-11-02 reproduced fourteen issues and reports a regression test
for each fix, seen to fail against the original code or a deliberate break of
the fix. The review's own lock
for the log was then found to survive the MCP client killing the gateway, which
blocked every later start, and was replaced by the kernel lock before release.
CI ran the full suite on Linux, macOS and Windows, including the race detector
on Linux. The report is `docs/AUDITORIA_2026-11-02.md`, in Spanish. The open
limits are in `SECURITY.md` and `docs/TECH_DEBT.md`.

Major rather than minor: the log format gained a field older verifiers reject,
the config format got stricter, and this release starts the compatibility
promise. Upgrading is still replacing one static file.
