### What changed

**Build provenance.** Every binary now carries a Sigstore-backed attestation
proving it was built by this repository's workflow, from this commit. That is
the `gh attestation verify` command below, and it is checked against GitHub
rather than against this page.

**A security policy.** [SECURITY.md](https://github.com/Jegoba90/Ganimedes-Project/blob/main/SECURITY.md)
says how to report a vulnerability privately, what a one-person project can
honestly promise about response times, and which limitations are already known
and written down rather than waiting to be found.

**The CLI stops stating things that are not true.** These came out of auditing
the published v0.1.0 binaries instead of the source:

- A tampered log was reported as `entry 1 of 1` when the log held more entries.
  The report now names the failing entry, states no total it cannot know, and
  says plainly that the entries after it were never checked.
- The help ended with "This is a v0 skeleton", inside the release that closed
  every v0 milestone and passed its smokes.
- `init` was advertised in that help and answers "not implemented yet". It still
  answers, it is no longer advertised.
- `ganimedes` with no command exited 0. Doing nothing is not success, so it now
  exits 2. That change is why this is a minor release and not a patch. Help that
  accompanies an error now goes to stderr whole, instead of splitting across
  stdout.

**v0.1.0 turns out to be reproducible.** All six of its binaries rebuild from
their tagged commit into the same bytes, differing only in the Go build ID that
records which machine did the building, and on darwin/arm64 in the one
code-signature page hash covering it. That release predates the attestation, so
this is what answers the same question for it.

Upgrading is replacing one static file.
