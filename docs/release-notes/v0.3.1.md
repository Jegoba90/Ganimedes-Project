### What changed

**A timed-out approval now tells you where it was waiting.** The error the agent
receives carries the address of the approval page, not merely the news that
nobody answered:

```
blocked by Ganimedes: approval for tool "write_file" timed out; it was waiting
for a human at http://127.0.0.1:8765/
```

That address is announced once, at startup, on stderr, and an MCP client files a
wrapped server's stderr into a log its user never opens. A timeout is also the
one outcome nobody chose: a deny was configured and a rejection was clicked, but
a timeout means the human never saw the request at all. The error travelling back
to the agent is the only channel left that reaches them.

**A second wrapped server no longer fails silently.** The approval page needs a
port to itself, and a client launches several wrapped servers from a single
config, so the second one to ask for `127.0.0.1:8765` exits at startup. It always
did; what the client showed was a server that would not start, with the reason
buried in a stream nobody reads. `run` now follows the bind error with a line
naming `--approval-addr`, which is the flag that fixes it.

**The README says what the log holds.** Entries store arguments and results
verbatim, so if an agent reads a file holding a token, that token is in the log,
which makes the log as sensitive as the traffic that produced it. It is created
`0600`, a mode POSIX honours and Windows ignores, so on Windows the directory is
what protects it. This was already written in `SECURITY.md`, `docs/DESIGN.md` and
`docs/GO_NO_GO.md`, and missing from the one document a person reads before
deciding where to put the file.

**A limit worth knowing before you trust an empty log.** A client brings tools of
its own and prefers them. Asked in plain language to read a file, Claude Code
used its own reader and never consulted the wrapped filesystem server, so the
audit log recorded nothing while the agent worked normally. Nothing evaded the
gateway there, because no call was ever made to it. An empty log means no traffic
through this server rather than an agent that did nothing.

**How this was found.** By walking the install and the first run as a new user
rather than as the person who built it, and then checking the result under a real
Claude Code session. That second half earned its keep twice. It confirmed that a
client shows a tool error's message verbatim, which is the assumption the first
change above rests on. And it corrected the wording: the message first read
`nobody answered at` the address, and the agent reading it concluded the approval
service was probably not running and offered to start it, when the page was up
and serving and a person was the only missing part.

Patch rather than minor: no flag, exit code or log format changed. Two diagnostic
messages got better and the documentation caught up with them. Upgrading is still
replacing one static file, and logs written by earlier versions still verify.
