### What changed

**A decision now has to come from the page itself.** `/decision` used to trust
any well-formed POST: an id and an action were enough to approve or reject a
pending call, with nothing proving a human had seen the page at all. A plain
HTML form on any page open in the same browser, pointed at the approval
server with hidden `id`/`action` fields and an auto-submit script, is a
same-origin-policy-compliant request — no preflight, no cookie, nothing a
browser refuses to send. The approval-list's whole guarantee, a human
decides, held only as long as nothing hostile was also open in a tab while
`ganimedes run` was up.

Every run now generates a random token, and every rendered form carries it as
a hidden field. `/decision` requires that field to match before it looks at
anything else in the request. A page from a different origin cannot read what
the approval server served it, under the same policy that let it POST there
blind, so it cannot produce a valid token — a click on the real page always
can. This does not add a login: the page is still loopback-only and
unauthenticated exactly as documented. It proves the request came from this
page, not who is sitting at it.

**Pending ids stopped being a plain counter.** They were 1, 2, 3... before
this release, so a forged POST that could not read the token still knew which
ids were worth guessing blind, and covering the first few dozen would catch
whatever was pending. Ids are random now, which also retired the one thing
the counter was doing double duty for: its order was the page's display
order. The page now sorts pending calls by the time they arrived instead, so
the longest-waiting call still leads the list.

**How this was found.** By reviewing the codebase against `SECURITY.md`'s own
list of what counts as in scope, rather than assuming the accepted
limitations next to it (no authentication on the page, a log that holds
secrets) were the only gaps left. One line on that list — "a cross-site
request that decides for you" — was a description of `/decision` as it stood,
not a hypothetical.

Patch rather than minor: nothing about the CLI, the config format, or the
audit log changed, and logs written by earlier versions still verify.
Upgrading is still replacing one static binary. If you run `ganimedes` with
an approval-list configured, upgrade before you next rely on it — this is the
class of bug `SECURITY.md` puts ahead of everything else in the queue.
